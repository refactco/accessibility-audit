Accessibility Audit, product build

How we build the auditor

State of 2026-10-16. The plan is PLAN.md, and the boards are STAGE-1.md to STAGE-7.md. The code is at github.com/refactco/accessibility-audit, version 1.0.0.

Three rules shape the work.

  • 1Build the full path early, with a small set of tests. Then add depth. Each stage works on the whole site.
  • 2Each step is proved on a test site with known faults before it runs on a real site. The correct site must give zero issues, and each fault must be found.
  • 3The auditor lists the issues and recommends a solution. It never fixes a site. Since 2026-10-14 no person is needed: two AI passes decide each question, and a second file hands the fixes to a fixing agent.

The seven stages of the plan

The plan has seven stages, in this order. Each stage has a "done when" check. All seven stages are done, and the product is at version 1.0.0.

One cycle of the product, with no person

This is what the product does on a site when you ask for the cycle. The engine lists the work of each step, and the skill starts one agent for each batch. The verifier never sees the first answers, so two equal answers mean something. A question where the two passes differ stays unresolved, and the report counts it.

One step of the build

Inside a stage, the work goes in steps. Each step follows the same loop. A step is one part of the engine, for example the page states, or one research question.

Where we are today

  • The product does its whole job with no person. A fresh session ran the cycle on the test site in 19 minutes with 7 agents. The weekly job ran it on refact.co in 100 minutes: 69 open issues, each with an origin, a source file, and a solution, and 69 tasks for the fixing agent.
  • The code is on GitHub, as a package with the command a11y and as a plugin with the skill. The refact repository has both installed, and one message in a session there runs the cycle.
  • The report opens with the accessibility overview. For level A and for level AA, it gives the share of the tested units with no failure, and the criteria met, failed, and unknown. It also gives the pages with no failure, the open issues by severity, and the history of the runs. It is a tool measure, not a conformance claim.
  • A scheduled job ran the cycle three times on 2026-10-15 with no help, in 100, 90, and 93 minutes. The check of stage 3 is met. On 2026-10-16 the job was removed by decision: not needed at this stage.
  • The install test passed on 2026-10-15: the user installed the auditor on a second site with the README alone, and the cycle ran with no help. 740 pages, 113 issues with a solution, and 113 tasks, in 96 minutes.
  • Version 1.0.0 on 2026-10-16, with the test for images of text, the last criterion with no test, and a fix of the pictures of the questions. Open after it: a sharper rule for cut text, and an expert on a sample of real issues.
